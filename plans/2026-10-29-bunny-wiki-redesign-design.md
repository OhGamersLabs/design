## 1. 意图

这个站是 Bunny 的设定资料库，读者是要按设定画她、做她的人：画师、动画、3D、宣传。改版要做到三件事：

1. **一眼看到现在的她**：进站第一屏就是已定稿的场景图和完整人物，旁边是身份信息，下面是最新四条成果。
2. **按设定集的顺序查规格**：身份与画风 → 身体基准 → 衣层由内到外 → 表情 → 武器与携行 → 动作与场景 → 下载。每一页只讲现行设计。
3. **历史有地方放，但不混进现行**：被取代的设计、旧稿、旧尺寸和改动原因都放进"历史档案"，现行页不再写过程。

## 2. 目标、非目标、反目标

**目标**

- 角色主页照效果图 A 重做：首屏、最新、章节条和七个段落。
- 衣层内页统一成一个模板：左侧层号卡，右侧依次是穿着三视、分件结构、细节。
- 新建历史档案页，所有历史图、旧尺寸和过程文字迁过去。
- 三张最新成果作为正式资产进站：场景定稿、STRUCTURE20 线稿、SUN-05 人体结构稿。
- 现行和历史的划分由每张图的审阅状态决定，不再靠手写的 `<details>`。
- 换上 Bunny 的橙、红、白、黑配色，删掉死代码。
- 所有旧 URL、旧锚点和旧标题锚点都能继续落到对应位置。
- 新增站点检查脚本，把本文档的文案规则、链接规则和资产规则变成机器检查。

**非目标**

- 不部署，不上传 R2，不改 `worker/`、`wrangler.jsonc`，`catalog/releases.json` 的 `contentReady: false` 也不动。
- 不画新图，不修图。新资产只做格式转换：PNG 转同尺寸 WebP，外加缩小的缩略图。移动端首屏按效果图 A 用 CSS 取景，不改图片本身。
- 站点首页 `docs/index.md` 只换配色、校正标语，不改结构。角色索引以后有第二个角色时再做。
- 不填 `/standards/`（通用规范）占位页，也不把它移出顶栏。
- 不做暗色模式（保持 `appearance: false`），不做其他角色。
- 不改尺寸数据 JSON 和标尺几何。

**反目标**（做出来就算失败，即使技术上能跑）

- 现行页能看到已取消的设计或过程词。
- 首屏不是现在的她，比如原稿、旧基准板或线稿占了主位。
- 图注写了图上看不到的部件，或者编造了事实：厘米身高、色值、日期。
- 现行页上左右写错，或者只写"左 / 右"不说明是角色的还是画面的。档案页里我们自己写的记录也照此写；原样搬过去的旧文字不改。
- 旧链接点进来 404，或者落到不相干的位置。
- 资产哈希检查被绕开：手改清单，或者改动、重编码已有的 WebP。
- 看起来像通用模板：紫色、全站圆角卡片、emoji 图标、渐变。

## 3. 必须守住的约束

1. **`ReleaseImage`**：
   - 现有行为全部保留：原生 `<dialog>`；Esc 关闭；点背景关闭；关闭后焦点回到打开它的那张图；"原始尺寸 / 适应屏幕"切换；原图链接带 `rel="noopener noreferrer"`；地址只接受 `/` 开头或 https。
   - 大图层显示的图不变：有原图时显示原图，没有时显示网页图。
   - 新组件只能包它一层，不另写大图层。新增能力见 4.8。
2. **原图地址**：
   - 原图链接仍是 `/media/<角色>/<版本>/<文件>`，由 `catalog/releases.json` 精确映射，未知路径 404。网页图仍是 `/characters/<角色>/<版本>/<名>.webp`。
   - 尺寸工具的标尺，"原图"仍指向 `/characters/.../*.svg`，不受上一条约束。
3. **清单与哈希**：
   - 以 `6cd6593` 为准，下列文件的 sha256 不变：已有的 180 张 3.1.0 WebP、19 张标尺 SVG、`origins/1.0.0` 下的文件、7 个尺寸数据 JSON（名单以 `6cd6593` 的文件列表为准）。
   - 清单只能由 `tools/build-local-catalog.py` 生成，两份 `manifest.json` 保持一致。
4. **尺寸工具**：
   - `body-measurements.mjs`、`garment-measurements.mjs` 路径不动。
   - 9 张标尺 SVG 由两个构建器重生成，`--check` 不能出现字节漂移。另外 10 张是冻结的旧文件，由 3. 的哈希固定。
   - 尺寸数据只展示、不重算。"未取点显示为 —、不给厘米"和"近似取点 / 可见取点 / 不赋值"这些说法保留。
   - 允许改组件的外壳文字、`<details>` 结构和"现行页显示哪些来源"的过滤，几何和 SVG 输出不变。
5. **发布闸门**：
   - `docs/characters/bunny/index.md` 的 frontmatter 里有且只有一处 `releaseReady: false`（和 `verify-release.mjs` 的检查一致）。其他页面的同名声明不要求清理。
   - `npm run check:release` 继续失败。
   - 主页信息框**新增**状态文字「本地审阅版，不是生产发布」（现在站内没有这句，只有 README 第 5 行有同义说法）。
6. **构建**：
   - 输出仍是 `docs/.vitepress/dist`；`npm run build` 现有四步的顺序不变；`npm test` 通过。
   - 不加运行时依赖；VitePress 1.6.4、Vue ^3.5.13、vite 6.4.3 不升级。
7. **自包含**：不引外部 CDN、字体或脚本，用系统中文字体。
8. **原始资料不进 git**：`.release/` 继续被 git 忽略；不提交凭证；不放候选稿。

### 4.3 内页模板（照效果图 A `#inner`）

- **左侧层号卡**：
  - 宽屏时固定在左，窄屏时收成页顶的一条。
  - 橙底，大号层号，页名，「第 N 层，共 0 到 8 层」，0–8 层的格子（当前层高亮，可点）。
  - 下面是 3–4 行事实，例如夹克的形制、领口、标志，以及在它之上还有哪几层。
  - 最下面是「左右识别」，说明角色左右在画面上的位置。例如：「OG 标志在角色左臂。正面图里它在画面右边，背面图里在画面左边。」
- **右侧正文**，三段：
  1. 「穿着三视」：正面、侧面、背面，穿到本层为止；
  2. 「分件结构」；
  3. 「细节」。
  - 页面现有的现行小节（例如腿带的屈髋关系、鞋带收纳）放在三段之后。
- **非衣层内页**（双匕首、图面尺寸、画风与配色、使用检查、下载）：同一个外壳，左侧卡写类别和本页小节目录，不写层号。
- **页底**：阅读顺序里的上一页、下一页。
- **Bunny 页面不用 VitePress 默认侧栏和右侧"本页目录"**：
  - 导航靠顶栏、主页章节条和内页左侧卡。
  - 实现要点：用 frontmatter 的 `layout` 指向全局注册的布局组件；组件里自己渲染 `<Content/>` 和 `.vp-doc` 样式；每页设 `sidebar: false`、`aside: false`。

### 4.10 文字规则

**各类文字的来源**

- **新写的文字**（首屏、信息框、层号卡、新图注、中文名称）：只用事实表。
- **保留的现行文字**（各内页的规格描述、画风标准、尺寸取点说明、使用检查清单）：
  - 可以保留，前提是不和事实表、清单冲突；删掉过程句和已取消名称；
  - Claude 逐页对照事实表过一遍；
  - 已知的错误要改掉：`application` 的刀鞘、`index` 里写死的张数；
  - 与事实表冲突的地方按事实表改，并列给负责人。
- **档案说明**：
  - 「已改为什么」取自现有页面文字、`review_status`、尺寸 JSON 里的 `superseded` 原因；
  - 日期只取明确记录：事实表、带日期的状态名、现有页面正文里写明的日期。不用 git 提交时间；没有就写「—」。

**哪些算现行页**：除档案页和跳转桩以外的所有构建页面，含站点首页和 `/standards/`。跳转桩只按 A7 ①② 检查，页内文字固定为中性的「本页已迁移，前往：<目标标题>」，目标标题取自映射表。

**现行页的禁用项**：在构建出的页面可见文字上检查，含 `alt`，不含网址和文件名；匹配方式是逐字子串匹配，加明确的例外清单，不做"整词"判断。

- **过程词**（封闭清单）：本轮、此前、已取消、取消、保留、旧、历史、尚未、待选、待补、改为、原有。
  - 例外：顶栏和链接文字「历史档案」。
  - 规格文字里不是指过程的用法也要改写，例如「保留银白主面」改成「保持银白主面」，「厘米身高尚未设定」改成「厘米身高未设定」。改写过的句子列给负责人。
- **已取消的设计名称**：耳机、兔耳、护套、刀鞘、吊带、锯、棍、大剑、黑曜石。
  - 例外：「抗锯齿」。
- **左右**：一律写「角色左 / 角色右」或「画面左 / 画面右」。
  - 例外：「左右识别」「左右翻看」「左右键」「左右肩宽」。
  - 侧面图的视图名也写明哪一侧，例如「角色右侧面」。哪一侧以清单状态名或现有页面写明的为准；查不到的进复核清单。
- **版本号**：只指 `X.Y.Z` 形式的发布版本。现行页里当前版本 `3.1.0` 每页最多一次。档案页搬来的旧文字里的旧版本号不动。
- **符号**：不出现 emoji，指 `\p{Emoji_Presentation}` 和带 VS16 的序列。「↗」「—」「·」照常使用。
- **其他**：
  - 不出现色值、厘米数字，唯一例外是「厘米身高未设定」；
  - 不出现事实表和档案记录以外的日期；
  - 不写「最容易画错」「一眼就能认出」这类编辑性断言。

**固定写法**

- SUN-05 人体结构稿的图注：现行页上是「SUN-05 人体结构稿，手中为占位杆」；档案页变更记录里是「现行：SUN-05 人体结构稿，手中为占位杆」。
- 主页信息框的状态文字：「本地审阅版，不是生产发布」。
- 完整人物正面图的图注不写「后腰」「交叉携行」。这条只配背面图，或看得到后腰的侧面图。
- 头部只戴什么，用正面写法：「头部只有护目镜」。
- 版本号每页最多出现一次：主页在信息框，档案页在页头，页脚不写。

## 9. 实现方的取舍（负责人已过目）

**和效果图 A 或 A 版落地说明不同的地方**

1. **页面合并更少**：
   - 只把 `face`、`expressions`、`assembly` 并进主页，把 `assembled` 并进双匕首内页。
   - `body-base` 保留为第 0 层「身体」内页，这样层号格 0–8 每格都能点进一页。
   - `visual-language`、`application` 也保留为内页，主页不至于太长，中文锚点也少搬家。
   - 落地说明原本要把使用检查搬进通用规范，这里不搬：那是 Bunny 专属的检查清单。
2. **两个层名和 A 不同**：
   - 第 6 层：A 的衣层条写「橙色夹克」，内页标题写「橙色外套」。统一用「橙色夹克」，这也是事实表的叫法。
   - 第 5 层：A 写「右大腿」，改叫「腿带」。只写「右」违反左右规则，写「角色右大腿」又放不进衣层条。
   - 其余层名照 A 的衣层条。
3. **左右写法比 A 严**：A 里的「左腿橙色过膝袜」「侧面」等，实现时写成「角色左腿」「角色右侧面」。档案变更记录里的「左袖袋」也写成「角色左袖袋」。
4. **最新第 3 条的标题**：A 把图注「SUN-05 人体结构稿，手中为占位杆」当标题，日期行写「姿势选定」。这里照检查条件 M3，标题写「SUN-05 冲刺姿势选定」，图注不变。
5. **「下载」内页比 A 全**：主页下载段照 A 列 26 项；「下载」内页列全部现行图和尺寸数据（A 只有主页这一段）。
6. **站点首页只换配色和标语**：A 里没有这一页。
